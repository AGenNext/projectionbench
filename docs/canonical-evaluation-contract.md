# Canonical Evaluation Contract

ProjectionBench evaluates purpose-bound, constraint-aware capability through governed graph artifacts.

## Universal Evaluation Record

Every evaluation must answer five questions:

```text
1. What was attempted?
2. Under what conditions?
3. How was it measured?
4. What happened?
5. Can it be trusted?
```

## Canonical Contract

```text
Subject
  -> Capability
  -> Objective
  -> Constraint
  -> Context
  -> Evidence
  -> Method
  -> Prediction
  -> Outcome
  -> Reconciliation
  -> Score
  -> Insight
  -> Trust
```

## Contract Fields

| Field | Meaning |
|---|---|
| Subject | The identity, theory, model, agent, framework, or artifact being evaluated. |
| Capability | What ability is being measured. |
| Objective | Why the evaluation is being performed and what success means. |
| Constraint | Boundaries that must be respected. |
| Context | Domain, environment, audience, geography, assumptions, and conditions. |
| Evidence | Source material, disclosed information, observations, or data. |
| Method | Metric, rubric, profile, evaluator, and scoring method. |
| Prediction | Generated claims, hypotheses, forecasts, or expected outcomes. |
| Outcome | Reference result, observed result, actual result, or accepted conclusion. |
| Reconciliation | Gap analysis between prediction and outcome. |
| Score | Quantified evaluation result. |
| Insight | Qualitative interpretation of the result. |
| Trust | Provenance, reproducibility, explainability, verification, and confidence. |

## ProjectionBench Profile

For the ProjectionBench scientific-hypothesis profile:

```text
Subject        = model or theory agent
Capability     = progressive scientific hypothesis generation
Objective      = converge toward reference paper conclusions as evidence is disclosed
Constraint     = only use information available at the current disclosure stage
Context        = scientific domain and paper metadata
Evidence       = progressive disclosure stages
Prediction     = generated hypothesis claims
Outcome        = reference paper conclusion claims
Reconciliation = semantic claim comparison
Score          = claim alignment, groundedness, novelty, consistency, stage improvement
```

## Generic Theory Profile

For generic theory evaluation:

```text
Subject        = theory, model, agent, person, team, organization, or framework
Capability     = explain, predict, revise, guide, or decide
Objective      = profile-specific success criterion
Constraint     = policy, evidence, domain, time, risk, and method constraints
Context        = domain, market, organization, geography, environment
Evidence       = source facts and disclosed information
Prediction     = implications, expected outcomes, or generated claims
Outcome        = observed result or accepted reference result
Reconciliation = what matched, missed, contradicted, or improved
Score          = weighted metric result
```

## Score Rule

No score is valid unless it links to:

- subject
- capability
- objective
- constraint
- context
- evidence
- method
- prediction
- outcome
- reconciliation
- provenance

## Trust Rule

A trustworthy benchmark result must be:

- reproducible
- traceable
- explainable
- versioned
- auditable
- linked to source artifacts

## Final Principle

ProjectionBench is not only a benchmark runner.

It is an artifact-native evaluation contract for testing whether theories, hypotheses, agents, models, and frameworks can produce useful claims under evidence, context, objective, and constraint.
